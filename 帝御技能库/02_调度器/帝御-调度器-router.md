# 帝御 · 调度器（Router）

## 功能定位

调度器是帝御体系的**唯一入口**。它不亲自做推演，而是判断用户当前需求属于哪一层、哪一诀、哪一部典籍、或是否触发总纲法则，然后路由到对应的技能文件加载执行。所有帝御系调用都应先经过调度器。

## 路由规则

收到用户需求，按以下优先级判断，输出【调度路由：已选择 XXX】：

1. **先判是否触发总纲法则（御物·无不可用）**：若需求中带有"不可控/不利/没用/没法"等判定，或需把不利转为有利、借势破局，先走「御物（无不可用）」视角——可用否→如何用→如何高效用，再落到具体层/诀。

2. **再判主框架层**（对应用户需求的主要性质）：
   - 情绪/修身/心态失衡 → 心法层
   - 竞争/博弈/资源取舍/方案对比 → 御势层
   - 被裹挟/自我定位/人生抉择 → 主见层（独见守己）
   - 决策压力大、需定心又需定策 → 兼有（多层并用）

3. **再判是否匹配某部典籍**：若需求高度契合某部子技能的「适用场景」，则路由到该子技能（见上表），并同时标注其主落点。

4. **主典 + 佐典**：若一处境可同时用多部典籍，先定一部主典（最能契合并能独立成推演），其余为佐典，一并列出。

5. **组合输出**：输出时先给「调度路由」标注，再加载对应技能文件执行推演；若用主文件即够，则标注主框架层即可，不必强行拉子技能。

6. **资源积累触发（2026-10-05 修缮补充）**：凡涉及资源/经济/积累/竞争类需求，默认路由到「凝本存资·凝争相成」（凝为保底常行、争为大方向伺机进取，二者双轨并行非场景二选一）；若需求涉及"资源落后/经济不足/份额被抢/竞争失败"等需争夺增量者，再用「争之三问」（兵法问/资本问/戮问）推演争夺胜负，按需联动：御势（《孙子兵法》何时争/争何处）＋ 权衡（《韩非子》识利、《三十六计》借势）。

## 观点级路由（2026-10-05 修缮补充 · 不升版本）

**适用**：复杂对局、多因素分析、需要逐点攻防的推演（如MOBA对局、项目多线评估、多方博弈）——当需求涉及多个独立子问题时，从"整篇路由到一典"升级为**逐观点路由到对应子技能**，使每个判断都有其技能依据，逻辑链可追溯。

**执行方式**：
1. 先把需求拆成若干**独立观点/子问题**（每个观点只含一个判断）。
2. 对每个观点分别路由：标注其依据的层/诀/子技能（如【依据：孙子·避实击虚】【依据：凝本存资·戮·夺资】）。
3. 观点之间按推演顺序串联成**逻辑链**（先定调、再评估、后出招、终收束），每个观点依附于前一个观点的结论。
4. 输出格式：观点 → 判断 → 【依据：子技能/层诀】；全部观点走完后给「帝御总判」收束。
5. **未明标注（2026-10-05 修缮补充）**：每个观点若信息不足、证据缺失、条件未齐，判断不得强行下结论——明确标注「尚且不明确」并给出"需补什么信息/如何验证"；观点级路由按主文件「判断说明·明断五步」执行（定向→开枝→检枝→对证→定策→未明标注）。

**示例（资源积累类）**：
- 观点"经济刷不起来" → 判断"积累有多路：凝（保底）与争（进取）——刷不起来多为凝断（顺手资源都没保住）与争败（增量没抢到）并存" → 【依据：凝本存资·凝争相成】
- 观点"能不能抢赢" → 判断"取决于争夺时机与对象；若对方动向未观察够，则『尚且不明确：需先记录对方刷野/游走节奏再判』" → 【依据：孙子·避实击虚 / 三十六计·借势】
- 观点"抢的代价" → 判断"先守己再夺资，送命换经济是反戮；争不动时凝守保底、等窗口再争" → 【依据：凝本存资·戮·守己夺资】

**约束**：观点级路由不替代需求级路由——先按「路由规则」定总方向（层/主典），再在展开时逐观点标注依据；观点依据不得跳脱已路由的总方向。

## 调度输出格式

> 【调度路由：已选择 XXX】
> 主典：XXX（文件夹路径）
> 佐典：XXX（如适用）
> 落点：XX层 / XX诀
> 执行：加载对应 SKILL.md，按其中「推演逻辑链」展开。

## 约束边界

1. 调度器只做路由分发，不亲自推演，避免越权。
2. 一次需求先定一个主典，不并行堆叠多个技能输出。
3. 若需求不在帝御体系覆盖范围（如纯事实查询、与决策/心性/博弈无关），直接告知并回落到常规对话。
4. 子技能自身的约束（如权谋类"不用于现实欺骗"）在路由时一并生效。

## 与主文件联动

- 主文件 `diyu/SKILL.md` 的「万法归宗」提供"经典→诀/层"映射索引，「御物·无不可用」提供"不可控→可借势"总纲法则；本调度器在其之上增加"需求→技能文件"的实际加载路由。
- 调度器新增/删除子技能或总纲法则时，需同步更新本文件清单，并保持与主文件版本一致（当前 v1.05）。
